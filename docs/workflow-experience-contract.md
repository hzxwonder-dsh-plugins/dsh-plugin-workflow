# 工作流交互与论文解读执行规范

## 目标与依据

用户通过少量完整任务步骤组织 Agent，上传材料后可以跟踪、补充、暂停和恢复执行。编辑器负责配置；运行页沿用 Desktop 会话布局，展示当前步骤和交付结果。

依据：用户确认的实时交互、独立暂停、步骤会话、公共目录快照、按次修改输入和验收后推送约束，以及四阶段论文解读需求。设计方法采用 product-design-and-ux 的状态与恢复模型，以及 ui-ux-pro-max 的可读性、语义主题、键盘和反馈原则。此规范不代表用户研究或真实读者测试结果。

## 页面职责

| 页面 | 核心内容 | 操作与完成证据 |
| --- | --- | --- |
| 工作流总览 | 名称、用途、会话数量、最近活动 | 打开编辑器、进入会话；导航后展示对应内容 |
| 编辑器 | 任务步骤、输入来源、输出、模型 | 对话修改、保存、试运行；调试方式在此选择 |
| 步骤设置 | 任务、模型、材料、参与者 | 高级配置按需展开；字段错误保留当前编辑内容 |
| 执行会话 | 当前步骤、轮次、输入、结论、文件 | 发送补充、暂停、继续；已完成过程折叠 |
| 评审记录 | 问题、回答、证据、评分和修订建议 | 可查看每轮记录；评分属于模型评价，不能作为事实正确性的证明 |

画布保持节点间可见间距，长内容在步骤设置中阅读。文字沿用宿主字体，低饱和度颜色仅辅助区分；状态同时显示文字。按钮使用统一图标与标签，焦点可见。窄窗口让工具栏换行、设置面板可收起，正文避免横向滚动。页面切换保留运行与草稿。

## 四阶段论文任务

1. 获取论文：根据附件、链接或检索请求确定原文，保存来源与文件；存在多篇候选时澄清。
2. 生成解读：调用指定 skill 和模板，生成有引用、实例和边界说明的初学者文章与相关文件。
3. 评审与修订：提问者读取原文和文章；回答者读取文章与问题；审稿者读取原文、文章和问答。依赖就绪后启动相应成员，不依赖的成员仍可并行。审稿反馈驱动第二阶段修订。
4. 发布：向配置的 Halo 位置提交达标稿，记录文章标识与访问地址；只有服务端成功响应并核实页面后才能显示发布成功。

## 输入与会话边界

子代理可声明自己的输入映射与依赖。未指定映射时保持现有继承行为；指定后仅传入映射材料，不自动附加原始附件。严格阅读者须使用独立会话且禁用文件、网络及其他可获取原文的工具。问题本身可能包含原文信息，评审时需区分提问透露的信息与文章所提供的信息。

循环配置包含起点、结束判据、轮数上限与会话方式：延续上次会话保留该步骤上下文；新建会话只传入明确配置的材料和反馈。两种方式都保留每轮产物、评审与执行记录。会话无法恢复时展示可处理的错误，不静默更换会话。

## 状态与恢复

| 状态 | 用户看到的内容 | 恢复方式 |
| --- | --- | --- |
| 获取材料失败 | 链接、错误、已有附件 | 更换材料或重试，不消耗评审轮次 |
| 运行中 | 阶段、当前成员、轮次 | 补充消息或暂停；隐藏页面不取消 |
| 需要澄清 | 一个具体问题及已有材料 | 回答后继续原运行 |
| 需要修订 | 评分、证据、修改建议 | 按配置返回写作阶段 |
| 达到轮次上限 | 最新稿与完整评审记录 | 保留现场，用户决定后续操作；不自动发布 |
| 发布失败 | 已生成稿、错误与已知文章标识 | 核实远端状态再重试，避免重复文章 |
| 发布完成 | 文章标题与核实后的网址 | 打开公开文章检查排版 |

## 已确定的配置

- 提问、回答、审稿依次执行，85 分通过，最多三轮。
- paper-explainer 使用经调研确认的分层阅读模板。
- Halo 使用现有论文分享分类，达标后自动发布；未达标暂停。

## 验收范围

需验证子代理输入隔离、依赖排序、并行兼容、循环上下限、会话延续与新建、暂停与恢复、调试步骤边界、版本冲突、重复发布恢复，以及明暗主题、长标题、窄窗口、滚动与键盘操作。真实模型、真实服务器发布与合成测试分别记录结果。仓库材料只使用合成数据，发布凭据留在服务器。
