# Desktop 工作流体验设计

## 使用目标

初次使用者可以找到已有工作流、理解任务步骤、提供材料开始执行，并从历史会话继续交流。编辑熟练者可以检查分支、修改输入、配置子代理和逐步调试。

设计依据：用户对 Desktop 原生会话、简洁布局、历史续聊、任务级步骤和编辑器调试的明确要求；实际 Desktop 界面检查；product-design-and-ux 与 ui-ux-pro-max 的交互和视觉指南。本文属于产品走查与文献调研，不代表新用户访谈或可用性实验。

## 调研与取舍

访问日期：2026-09-20。

| 来源 | 观察 | 本产品采用方式 |
| --- | --- | --- |
| [n8n 首个工作流](https://docs.n8n.io/try-it-out/quickstart/) | 创建、添加步骤、配置、单步查看输出、整体验证形成明确路径；添加节点使用搜索和选择 | 常用步骤直接可见，扩展步骤通过菜单进入；配置跟随所选步骤 |
| [Jupyter Notebook](https://jupyter-notebook.readthedocs.io/en/stable/notebook.html) | 单元承载输入及结果；工具栏提供常用操作；重新打开连接原交互会话 | 步骤输入与产物相邻；历史打开原会话；运行和查看过程分层 |
| [NN/g 渐进披露](https://www.nngroup.com/articles/progressive-disclosure/) | 首层保留常用功能，高级功能放在明确可见的次级入口，避免过多层次 | 步骤列表作为默认入口，流程图按需进入；保留一层“更多步骤” |
| ui-ux-pro-max：Minimalism & Swiss Style | 留白、字级、单一重点、明暗主题一致 | 宿主字体和语义颜色、轻边框、统一按钮和间距 |
| product-design-and-ux：Interface Contracts、AI Interaction | 说明状态、恢复路径与行为证据；AI 结果不等于事实保证 | 保留运行状态、调试、人工采用结果及失败恢复；不改变模型评分边界 |

初始自动设计系统搜索返回了营销页面结构，产品类型不匹配；采用随后明确匹配的工具界面风格结果。渐进披露的本地关键词搜索未匹配，相关决策采用已读取的 NN/g 原文。Dify 文档读取失败，未作为依据。

## 界面结构与状态约定

| 页面 | 首要内容和操作 | 次级内容 | 恢复与重入 |
| --- | --- | --- | --- |
| 总览 | 搜索、工作流用途、运行、历史对话 | 编辑、复制、归档 | 搜索无结果可清除；卡片/列表选择保留；历史继续原 ID |
| 编辑器 | 步骤列表、任务说明、试运行 | 流程图、版本发布、更多步骤、JSON | 视图切换保留草稿与所选步骤；视图偏好保留 |
| 步骤设置 | 选中步骤的任务及材料 | 模型、子代理、循环、高级配置 | 修改仍使用现有草稿和保存机制 |
| 执行会话 | 当前状态、输入、结论和文件 | 过程、尝试记录、独立步骤会话 | 隐藏不停止；历史重入；续聊与新运行有明确入口 |

步骤列表中的序号用于定位，执行顺序仍由依赖关系决定；每项展示来自哪些步骤的材料。流程图与步骤列表共用同一份定义，切换视图不改变连线。模型、子代理和循环均保持已有执行行为。

编辑器将“运行记录”直接命名为目标内容。试运行是主要动作；发布只针对已保存的新版本。调试配置保留在编辑器。总览历史行只负责打开历史及其管理操作，新任务通过卡片的运行入口开始。

## 可观察验收目标

- 无需理解图连线即可选择步骤并修改任务。
- 从更多步骤添加工具后可撤销，原定义恢复。
- 切换列表与流程图不丢失草稿、选择和材料关系。
- 搜索无结果有清晰解释和恢复入口。
- 历史续聊使用原会话，刷新后消息仍保留。
- 明暗主题均可读，窄窗口不遮挡主要操作，键盘焦点可见。
- 真实 Desktop 加载相同构建并验证入口与导航。

## 工程组织

总览与历史入口集中在 client/gallery.jsx；步骤概览为 client/step-outline.jsx；运行仍由 run-timeline、step-input 和 native-step 组件承载。基础会话样式的重复规则已归并，组件共用宿主语义主题。

正式新用户研究仍需真实参与者完成创建、运行、修改和续聊任务，记录成功率、完成时间与误操作。本次使用合成材料进行功能验证，不将工程师走查结果表述为用户研究结论。
